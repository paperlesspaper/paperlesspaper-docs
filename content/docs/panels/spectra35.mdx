## What Spectra35 does

A normal Spectra6 update selects six native colors. Spectra35 combines **a per-pixel native starting color with a sequence of custom waveforms** to retain additional pigment states on the tested 13.3-inch OpenPaper L. Epdoptimize then dithers against a 35-entry appearance palette.

“35” counts recipe entries. It does **not** establish 35 independently distinguishable, stable colors on every panel. Some states are close together, and fine dither patterns can look different from large swatches. The experiment is separate from the earlier [16 image-code photo rendering](/panels/dke-13-3-inch/display-control#color-photos-with-less-grain), which used an ordinary refresh.

| Stage | What it contains |
| --- | --- |
| Appearance palette | Approximate camera-derived RGB values used for matching and dithering |
| Token image | One exact recipe ID per pixel, encoded as an RGB token |
| Recipe table | The native history, waveform bank and LUT associated with each ID |
| Write plan | One native preparation followed by four complete LUT/image passes |

The tested raster is **1600 × 1200**, split across two controllers. Both reported `0x34C2`; this identity check alone is not a guarantee that another panel is compatible. See the [OpenPaper L panel guide](/panels/dke-13-3-inch) for the bench specimen and the [testbench setup](/manufacturing/testbench).

## 1. Use appearance RGB for dithering

Each entry has two deliberately different values:

```json
{ "name": "C04", "color": "#C44F45", "deviceColor": "#010003" }
```

`color` is the approximate appearance of that red recipe. Epdoptimize uses it when choosing pixels and distributing error. `deviceColor` is **recipe index 3**, carried as RGB `(1, 0, 3)`. It is not the red shown on the display and not a directly writable panel code.

This distinction also exists in Spectra6: its measured red can be dark and muted while its native export color is full RGB red. Spectra35 extends that mapping to **recipe tokens**, because more than one native refresh is needed.

The source palette SHA-256 is <code style={{ overflowWrap: "anywhere" }}>c829d104627fcf7e7666ef24b4733809fdeb0947a95900e6df537b3850bf26c0</code>. Values retain the measured recipe order. Names such as `black` and `white` identify reference states, not ideal RGB endpoints. Tokens run from `#010000` through `#010022`, corresponding to indices 0–34.

## 2. Generate a preview and an exact token PNG

Fit or rotate the original to **1600 × 1200 before dithering**. The example uses four separate canvases: `input`, `adjusted`, `preview` and `tokens`. It uses automatic dither selection with fixed neutral adjustments, rather than the later scene-tuned v3 preprocessing.

```js
import {
  applyImageAdjustments,
  ditherCanvas,
  replaceColors,
  suggestCanvasDitherOptions,
} from "epdoptimize";

const response = await fetch("/panels/spectra35/palette.json");
if (!response.ok) throw new Error("Could not load Spectra35 palette");
const palette = await response.json();
const automatic = suggestCanvasDitherOptions(input, palette, { intent: "natural" });
const options = {
  ...automatic.ditherOptions,
  palette,
  processingEngine: "js",
  calibrate: true,
  toneMapping: { mode: "off" },
  clarity: { amount: 0 },
  dynamicRangeCompression: { mode: "display", strength: 1 },
  levelCompression: { mode: "off" },
  paperNormalization: { mode: "off" },
};
await applyImageAdjustments(input, adjusted, options);
await ditherCanvas(adjusted, preview, options);
replaceColors(preview, tokens, palette);
// Export tokens as an opaque, lossless PNG for the offline planner.
```

The preview uses appearance colors. The token PNG will look almost black because every pixel is an ID near `#010000`. Do not resize, interpolate, JPEG-compress, color-convert or re-dither it after replacement. Unknown or transparent pixels must be rejected, not mapped to the nearest recipe.

For uniform fields or an undithered ramp, set `ditheringType: "quantizationOnly"`. This chooses among the existing states; it does not create a continuously smooth color space.

## 3. Compile the five-pass plan

Unpack the recipe kit, create an environment and compile the exact token image:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python compile_plan.py tokens.png new-plan
```

The output contains `indices.png` and `passes/plan.json`, five image streams and four LUT binaries. Existing output directories are rejected. This planner retains the full image and all four measured LUT passes even if only a few recipes are used. It does not insert a color strip.

| Pass | Action |
| --- | --- |
| 0 | Prepare every pixel using its recipe's native Spectra6 history |
| 1–4 | Upload the corresponding complete 2048-byte LUT and the exact bank-selection mask, in the recorded order |

A mask value selects a waveform bank; the final color also depends on pigment history. The full measured order is part of the palette definition. A recipe index is **not** a four-bit native pixel code.

## 4. Execute only with a matching experimental driver

The ZIP is an **offline adapter**, not a stock-firmware upload tool. Its transport files rotate the logical raster into two 600 × 1600 controller images, pack two four-bit selections per byte and compress 100 blocks per controller. Each block decodes to 4800 bytes and carries a little-endian 16-bit compressed length. These are bench transport files; other drivers must adapt them explicitly.

Before each refresh, check the complete LUT SHA-256, transport SHA-256 and both controller raster hashes in the plan. Require verified staging and natural BUSY completion for power-on, refresh and power-off. A rejected transfer must not trigger refresh. Inspect saved state before retrying; if the starting pigment history is uncertain, prepare a fresh complete run.

The bench needed paced UART transfers and temporary camera-stream pauses to avoid USB/UART data loss. Packet sizing is a transport detail, not reduced image bit depth. It does not change the 35 recipe values. The later linear-light image adapter does round to 8 bits per channel separately; this can coarsen dark input differences.

During a split comparison, inactive masks use bank 0 / Source0. **Source0 is an experimental hold candidate, not electrically verified HiZ.** Keeping that mask unchanged does not prove the other half is optically unaffected. Compare unchanged regions and the reference card before and after the custom passes.

## What is confirmed, provisional and still missing

| Status | Finding |
| --- | --- |
| Confirmed on the test unit | Exact token decoding; full 2048-byte LUT uploads; five ordered passes with checked raster/LUT hashes and natural BUSY completion |
| Confirmed observation | Fine 1-, 2- and 4-pixel mixtures can differ from uniform swatches; a solid-field palette alone does not predict every dither texture |
| Provisional | Camera-derived appearance RGB and extra retained states; two fresh chart builds and both halves were sampled, with position and repeat variation retained as uncertainty |
| Provisional | Improvements on selected photographs and colors; the v3 correction was tuned on the lake, and did not generalize cleanly to every motif |
| Open | Consistently neutral skin tones and monochrome photos; at least 16 useful neutral grays; long-term drift and endurance; transfer between panel units |
| Open | Absolute Source and VCOM voltages, measured with suitable instruments; Source0 high-impedance behavior; a production firmware/API integration |

Palette measurements used an in-frame reference card, fixed camera settings and disabled sharpening. They are approximate camera RGB estimates, **not spectrophotometer measurements or an ICC profile**. Later photos were captured separately; lighting, camera startup transients and geometry still affect comparisons.

### Build times

Recent split builds took approximately **256 s** (lake), **274 s** (flags), **329 s** (building) and **315 s** (poster). These times include staging, cooldowns and an intermediate capture, but exclude the final capture/archive overhead. The earlier 120-second photo target was not met. These results do not claim fast full-color animation or a flash-free native preparation.
