### Use this rendering in a project

1. Crop and resize the RGB image to its final pixel dimensions. For a full OpenPaper 7 image, use **800 × 480** in landscape.
2. Model the six inks with their [measured sRGB values](/panels/dke-7-inch#solid-colors). Convert to linear RGB and normalize each channel to the measured paper black and white.
3. For the orange photo, apply an S-curve to lightness in the paper range (**exponent 1.25**) and multiply Lab chroma around the paper’s neutral axis by **1.30**. Preserve black and white endpoints.
4. Dither with serpentine Floyd–Steinberg using the measured colors to calculate error. Write each winning color’s **native RGB code** to the output PNG. Keep those pixels at their original size and bypass any second round of dithering. [Curve, stronger setting and photo comparisons](/panels/dke-7-inch#orange-photo-contrast-and-chroma).

Download the [OpenPaper 7 photo renderer (ZIP)](/panels/dke-7-inch/2026-11-21/oranges/openpaper7-renderer.zip?download=1). Unzip it, then run the following in that directory on macOS or Linux. The defaults reproduce the tuned side of the slider.

```sh
python3 -m pip install numpy Pillow colour-science
cc -O3 -fPIC -shared diffuse.c -o diffuse.so -lm
python3 render.py cropped-photo.jpg device.png
```

## Choosing colors for each image

A six-color frame can show an orange area by mixing pixels. In the tuned fruit, **71% of the pixels were red, 23% yellow and 5% white**. Changing the mixture trades texture for accuracy. Restricting the fruit to red and yellow made flat patches smoother, while allowing neutral pixels helped match the source color. For photos with several hues, the measured six-color palette gives the ditherer access to all six inks. [Mixture photographs and results](/panels/dke-7-inch#redyellow-mixtures-in-the-orange-photo).
